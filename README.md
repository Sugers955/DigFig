# DigFig

面向企业办公场景的 AI 数字员工平台。以「数字岗位」为单位交付能力：把可标准化的办公流程交给 AI 执行，人负责定义规则、把住关口、处理例外。

一个数字员工由四部分构成——**岗位职责、工具权限、知识范围、人机交接规则**。四件配齐才是可上岗、可审计、可复制的数字员工，而不是一段提示词。

## 核心特性

- **岗位化定义**：按岗位职责建模，输入输出、验收标准、禁止事项写进配置，支持版本化与灰度发布。
- **多步流程执行**：任务自动拆解为步骤，按序调用工具，可在关键节点暂停等待人工确认，完成后交付成品（表格、文档、消息、报告）。
- **企业系统连接**：文档、表格、IM 消息、邮件、审批、知识库等系统通过适配器接入，鉴权与数据契约统一收敛在连接层。
- **多模型路由**：模型供应商可替换，按岗位、任务类型、成本与延迟策略路由到不同模型。
- **知识范围限定**：每个岗位只能检索被授权的资料范围，答案标注来源，跨部门数据默认隔离。
- **执行留痕与回溯**：每次工具调用的输入、输出、决策依据按 trace 记录，问题可定位到具体步骤。
- **权限与安全边界**：最小权限原则，凭证由环境变量或企业密钥管理注入；删除、外发、提交审批等敏感动作强制人工确认。
- **效果评测**：岗位级评测集与回归基线，改动流程或换模型后可量化比对准确率与耗时。

## 应用场景

- **财务与数据岗**：对账、凭证资料整理、异常清单生成、周期报表汇编
- **运营与分析岗**：多源数据汇总清洗、指标周报、看板数据准备
- **知识与服务岗**：内部制度与资料问答、常见问题自动应答并转人工
- **流程与协同岗**：材料收集催办、会议纪要与行动项整理、跨系统信息搬运

## 架构

```
接入层  Web 控制台 · IM 入口 · 开放 API
编排层  任务规划 · 流程引擎 · 工具调用 · 人工闸口
能力层  模型路由 · 知识检索 · 文档表格处理 · 内容生成
连接层  企业系统适配器（统一鉴权与数据契约）
治理层  权限 · 审计日志 · trace 回溯 · 效果评测
```

## 快速开始

### 环境要求

- Docker 24+，Docker Compose v2
- Python 3.11+（编排服务与工具执行器）
- Node.js 20+（控制台前端构建）
- PostgreSQL 15+，Redis 7+（容器部署时自动拉起）

### 启动服务

```bash
git clone https://github.com/Sugers955/DigFig.git
cd DigFig
cp .env.example .env      # 填入模型服务地址与密钥、数据库连接
docker compose up -d      # 启动服务端、控制台、数据库与队列
```

启动完成后访问 `http://localhost:3000`，使用初始管理员账号登录。

### 创建第一个数字员工

1. 控制台进入「数字员工 → 新建岗位」，从模板选择一类岗位（如「周度数据汇总」）。
2. 填写职责描述与输出要求，指定可访问的知识库范围。
3. 在「工具权限」中勾选允许调用的系统操作，敏感动作保留人工确认开关。
4. 点「试运行」跑一条真实任务，查看 trace 与成品，确认验收标准。
5. 提交审核并发布上岗，按周期或事件触发执行。

## 配置说明

所有配置通过环境变量注入，完整清单见 `.env.example`。关键项分组：

- `DIGFIG_MODEL_*` 模型服务地址、密钥、默认模型与超时
- `DIGFIG_DB_*` / `DIGFIG_REDIS_*` 数据库与队列连接
- `DIGFIG_AUTH_*` 控制台登录、组织与角色权限策略
- `DIGFIG_TRACE_*` 执行留痕级别与保留周期

两条硬性约定：密钥类配置不写入代码库，`.gitignore` 已排除 `.env`、`*.key`、`credentials.json`；岗位配置与系统配置分离，岗位配置独立版本化。

## 开发指南

```bash
make dev          # 本地起编排服务与控制台
make test         # 单元测试与流程回归
make lint         # 代码风格与类型检查
```

- `main` 分支保持可发布状态，功能开发走短分支加 PR 评审。
- 提交信息沿用 Conventional Commits（`feat:` / `fix:` / `docs:` / `chore:`）。
- 新增企业系统连接器时，同步补齐鉴权说明、失败重试策略与最小权限清单。
- 涉及数据外发、删除、提交的工具，必须保留人工确认开关，不得在实现中绕过。

## 部署

支持公有云 SaaS 与企业私有化两种交付形态。私有化部署通过 Docker Compose 或 Kubernetes Helm Chart 完成，数据与模型调用可全部留在企业内网；对外接口走开放 API，与控制台共用同一套权限与审计策略。
