# DigFig

面向企业办公场景的 **AI 数字员工**产品。以"数字岗位"为单位交付能力：把一个可标准化的办公流程交给 AI 执行，人只负责定义规则、把住关口、处理例外。

> 仓库状态：当前仅含文档骨架，代码尚未导入。文中 **【待确认】** 与标注「待代码导入后补充」的位置都需要产品或工程负责人填入真实信息，请勿对外引用未确认内容。

## 为什么做这个

企业里真正消耗人力的，往往不是判断和创造，而是**可标准化的重复执行**：整理表格、核对数据、汇总材料、按模板出文档、跟流程、答重复问题。

现有两类工具各缺一半。传统 RPA 能自动点击，但流程一变就得重录，且完全不懂内容；通用大模型能理解和写东西，但只能一问一答，接不进企业系统，也没有权限、留痕和交付标准。

DigFig 的取向是把这条缝补上：一个数字员工 = **岗位职责 + 工具权限 + 知识范围 + 人机交接规则**，四件配齐才叫上岗，而不是一段提示词。

## 核心能力

- **岗位化定义**：按岗位职责而非 prompt 配置数字员工，输入输出、验收标准、红线明确写进配置，可复制、可审计、可版本化。
- **多步流程执行**：接一个任务后自行拆解步骤、按序调用工具，中途可暂停等待人的确认，完成后产出可验收的成品（表格、文档、消息、报告）。
- **企业系统连接**：通过适配器接入企业的文档、表格、IM 消息、邮件、审批与知识库等系统。已支持清单见【待确认】。
- **知识范围限定**：每个岗位只能检索被授权的资料范围，答案标注来源；跨部门资料默认隔离。
- **执行留痕与回溯**：每一次工具调用、输入输出、决策依据按 trace 记录，出问题能定位到具体哪一步。
- **权限与安全边界**：最小权限原则，凭证不落盘不进代码库；删除、外发、提交审批等敏感动作默认需人工确认。

## 典型岗位场景

以下为产品定位下的目标场景方向，实际交付范围以版本说明为准：

- 财务与数据岗：对账、凭证资料整理、异常清单生成、周期报表汇编
- 运营与分析岗：多源数据汇总清洗、指标周报、看板数据准备
- 知识与服务岗：内部制度与资料问答、常见问题自动应答并转人工
- 流程与协同岗：材料收集催办、会议纪要与行动项整理、跨系统信息搬运

## 架构概览

分五层，具体技术选型随代码导入后补充：

1. **接入层**：Web 控制台、IM 入口、开放 API
2. **编排层**：任务规划、流程引擎、工具调用与人工闸口
3. **能力层**：模型路由、知识检索、文档与表格处理、内容生成
4. **连接层**：企业系统适配器（统一鉴权与数据契约）
5. **治理层**：权限、审计日志、trace 回溯、效果评测
